締め請求書の発行API — 受注から請求書までを API だけで1本に通した

請求先・締め日の単位で売上をまとめて請求書を作る API を作り、受注 → 分納での出荷 → 締め請求書の発行を端から端までテストした。二重請求は Domain・DB・売上の版数の3段で止める。AI レビューが4回走り、取り返しのつかない入力と金額の境界を見つけた。

06今日学んだこと

決定は1つずつ正しくても、組み合わせると穴ができる。決定の文言でなく、理由の方を実装する。

  • 「取り消せない」なら、入力の範囲を狭くする。取消を作らない決定と、未来の締め日を許す実装が組み合わさると、締めが全部できなくなる
  • 件数の検査は金額の検査の代わりにならない。「売上が無ければ作らない」の理由は「0円の請求書になるから」だった。返品で0円以下になる場面が漏れていた
  • 同時に起きることは割り込んで再現する。HTTP を順に呼ぶだけでは起きない。保存の直前に割り込んで 500 を確かめてから直した
  • 日付は「どこの今日か」まで決める。CI は UTC。日本時間の 10/31 0時は UTC では 10/30
