02ユースケースと API

入口で役割を確かめ、省いた値と円未満は Domain に渡す前に 400 で止める。登録すると Domain が古い請求書から充てる。

入力の検査省略・円未満は 400
請求先と請求書を読む無効の請求先も受ける

保存して返す201
表2　API /receipts
呼び方役割返すもの

  • 省いた時: 入金日・入金額を nullable で受け、省くと「入れる」と返す。0001-01-01 や0円で通さない（前日に書いた「省いた時」の行への答え）。
  • 円未満: Money は端数を丸めずに例外を出すので、手前で止めないと 500 になる。
  • 同時の取消: 一意インデックスが止めた時は 409「同じ入金の取消は、ほかの人が先に登録した。読み直してからやり直す。」
  • 役割の表: 「入金の登録・取消」を、まだ無い行の一覧からユースケースのある行へ移した。

06今日学んだこと

テストが通ることは、柵が効いている証拠にならない。データが誤りを見せる形になっているかを確かめる。

  • 順の指定は、データが並びを崩さないと試せない。書き換えない行は入れた順に返るので、わざと書き換えて崩した。
  • 日付の境目は「UTC ではまだ前日」で突く。日本時間 0:30 に止めると、今日を UTC で決める誤りが3か所とも落ちた。
  • 思い込みで「上書きされた」と書いていた。Git Bash の TZ=Asia/Tokyo date はこのマシンでは UTC を出す。Day55 で手で書いた「00:35」は UTC で、自動の書き出しの「09:34」が正しかった。sales-core の Day55 の決定の記録は今日のコミットで直し、計画シートの Day55 の記述も直した。
