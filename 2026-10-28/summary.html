03テストと対照実験

テストの利用者に差し替えず、本当にログインして呼ぶ。ログイン・トークン・入口の検査・保存の作成者まで一続きで確かめる。

  • 権限の実効性: 営業のトークンで締めると 403 で、請求書は0件のまま。同じ要求を経理のトークンで送ると 201。
  • 有効期限: 3600秒。テストの時計を進めて、59分後は使え、60分で 401。
  • 失敗: パスワード違い・利用者が無い・入力が無い・無効にした利用者は、すべて同じ 401 と同じ文言。5回間違えると、正しいパスワードでもロック。
  • トークンが無ければ 401 と WWW-Authenticate: Bearer。/account/refresh は 404。作成者にはその利用者の Id が入る。
  • 先に RED（ログインが無いので7件落ちる）を見てから実装した。

06学んだこと

権限の効き目は、差し替えでなく本物の経路で確かめて初めて分かる。

  • 本物の経路で確かめる。差し替えた利用者では、トークンの読み取りが壊れても気付けない。本当のログインで、作成者が空という配線の穴まで見つかった。
  • 検出しない実験は切り分ける。2通りとも .NET が代わりにやっていた。実測の日付と一緒にコメントへ残し、後で迷わないようにした。
  • 規則を1か所にまとめる。Cookie とトークンで方式が違っても、規則は同じユースケースと同じ設定を通る。
  • 応答の中身は1回しか読めない。期待は先に1回だけ読んで変数に入れる。

つまずき

  • ログインの後、呼んだ側で応答を読むと「Cannot access a closed Stream」 → ストリームで読んで閉じられていた → 文字列で読む。
  • API 経由の保存で作成者が空 → テストの差し替えに「操作した人」の出どころを渡していなかった → 渡す形にした。
  • 決定の記録が Study 側にできた → 前日と同じ → 秘密情報が無いことを見てから sales-core へ移した。
