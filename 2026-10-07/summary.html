02対照実験：EF Core の既定は、削除を連鎖させる

「外部キーをすべて RESTRICT」の2行を外すと、必須の外部キー13本がすべて CASCADE になった。

得意先を1件消すと、その得意先の受注・明細・出荷・売上が連鎖して黙って消える構造だった。EF Core としては自然な既定でも、このシステムの「物理削除しない」と逆を向く。C# の差分には ON DELETE CASCADE は現れないので、SQL を読む手順が要る。結合テストでは、明細のある受注を SQL で直接消そうとして、DB が SQLSTATE 23001（RESTRICT）で止めることを確かめた。

06今日学んだこと

道具の既定と業務の決まりがぶつかる場所は、生成物（SQL）を読まないと見えない。

  • EF Core の既定は、業務の決まりと逆を向くことがある。必須の外部キーを CASCADE にするのは自然な既定でも、物理削除しないこのシステムでは事故になる
  • 一意制約は NULL を素通りさせる。C# の string を見ても NULL を許すかは分からず、SQL の NOT NULL の有無で初めて見えた
  • レビューは「観点の表」と「別の目」の両方で効いた。前者は形（NULL 可否）、後者は業務の意味（同じ日に税率が2つ）を見つけた
  • SQLSTATE はテストの精度を上げる。23001 と 23503 を区別すると、RESTRICT が付いていることまで確かめられる
  • テストの期待値も、独立に計算して確かめる。テストの側を直すときは、根拠を明示する

つまずき

  • 変数経由の Remove-Item をハーネスが止めた。実行前に文字列で判定するので、変数の中身が分からず最悪を想定した。ファイル名を確かめてから -LiteralPath で明示して消した
  • PowerShell 5.1 に ?? 演算子が無い。if で書き直した
