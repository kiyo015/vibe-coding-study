01安全柵が黙って無効になっていた

設定・テスト・guard-e2e の合格がそろっていても、実際には別の経路で止まっていた。読み込まれたことを、起動時の記録で確かめるまでは効いていない。

図表2: 読み込み元（起動時の記録の plugins）
時点Studysales-core
前日までvibe-study（ローカル・作業中のソース）同じ登録を読んでいた（GitHub 配布ではなかった）
今朝 00:17 以降—読み込まれない（GitHub 版がキャッシュに無い）
直した後vibe-study-local（作業中のソース）vibe-study（GitHub v1.3.1 のキャッシュ）
  • 直し方（本人の決定）: Study のローカル用の目録を別の名前（plugins/.claude-plugin/marketplace.json、vibe-study-local）にした。sales-core には GitHub の版を claude plugin marketplace add と install で入れ直した
  • 再発の防止: guard-e2e の sales-core のセルは、読み込み元が dev-guard@vibe-study でなければ合格にしない。対照として、期待をわざと違えると判定不能になることを確かめた
  • 途中のつまずき: marketplace remove をリポジトリの中で実行すると、プロジェクトの設定からも登録が消えた（戻した）。claude -p は、バックグラウンドの取得を終える前に閉じる

止まらなかった DB 破壊のコマンドも、--dry-run と存在しないプロジェクト名（Day19 に決めた2重の安全）のおかげで、何も消えなかった。

02初日に安全柵を確かめる手順

新しく参加した人が、自分の機械で「止まって実行されない」ことを15分で確かめる。どの項目も、止まらなくても何も壊れない形にした。

図表3: 確認の6項目と、直した後の結果

1・2DB を壊すコマンド（Bash・PowerShell）pre-bash-guard で止まる
3強制 push（--dry-run、PowerShell・Bash）pre-bash-guard で止まる
4・5.env の読み取りと、同じ中身の別名のファイル（対照）.env は読めない／対照は読める
6編集後の自動テスト全件パス（混んでいると 60秒で打ち切り）
