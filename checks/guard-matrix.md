# 経路×ガードの表

設定したガードが**実際の経路で効いているか**の一覧。次月ロードマップのテーマA。

「設定した」と「効いている」は別物。Day7（worktreeの隔離が未追跡ファイルに素通し）、Day11（PowerShellツールにフックが効いていなかった）、Day13（無人実行の`--tools ""`が消えていた）は、どれも設定した時点では気づけなかった。

## 検証状態の区別

- **自動** — `checks/guard-e2e.js`が本物の`claude -p`で対照実験付きで確かめる。ガードを外すと不合格になることも確認済み
- **手動** — 手で1回確かめただけ。その後の変更で壊れても気づけない
- **未検証** — 効くはずだと思っているだけ

## 分かったこと

- **ガードは知らないうちに重なっている。** 対照実験で「フックなしなら実行される」はずが、Claude Code本体の「怪しいパス」検知（`SAKAGU~1`のような8.3形式）に止められた。自分で設定していない層があると、ガードを外しても止まり続け、**自分のガードが効いているのか別の層が効いているのかを区別できない**。対照実験の対象は、他の層に引っかからないもの（作業フォルダ内の存在しない名前）を選ぶ
- 判定では「別の仕組みに止められた」を「ガードで止まった」と分けて扱う。一緒にすると、フックが壊れていても緑になる
- **ガードの効き方には2種類ある。** フックは「試みて止められる」ので差し戻しの文言が残る。`tools`制限は「書く道具がそもそも無い」ので試みることすらなく、文言も残らない（サブエージェントは「持っているのはRead・Grep・Globだけ」と答えた）。後者を副作用（ファイルができたか）だけで判定すると、**サブエージェントが起動せずに終わった場合も合格に見える**。起動・完了の記録（`task_started`／`task_notification`）と、書き込みを試みたのが誰か（`parent_tool_use_id`）も合わせて見る
