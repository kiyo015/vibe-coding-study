# 学習セッションのクローズ作業

バイブコーディング学習のリポジトリ（このスキルが置かれているプロジェクトのルート。以下、パスはすべてそこからの相対）で、その日の学習内容を記録に残すための定型作業をまとめて実行する。Day1〜3で毎回手作業で繰り返していた手順をスキル化したもの。

## なぜこの手順か

学習の価値は「その日何をやったか」が後から追える形で残ることにある。手順を省略すると、次回セッション開始時に前回の到達点が分からなくなったり、GitHub上の学習記録が古いままになったりする。特にDay1で復元不能になった過去の失敗（バージョン管理前にファイルを上書きして過去の状態を失った）を繰り返さないよう、**必ずcommitしてから記録を書く**順序を守る。

`Study`全体が単一のgitリポジトリ（`vibe-practice`も配下に含む）。個別に`vibe-practice`だけコミットする必要はなく、下記Step1・Step2の変更を含めてStep3で一括コミットする。

## 手順

### 1. 今日の学習内容をまとめる

`{YYYY-MM-DD}/summary.md` をプロジェクトルート直下に新規作成する（日付はその日の日付）。構成は以下を踏襲する（Day1〜4のsummary.mdを参考にする）:

- タイトル・対象Day
- 今日学んだこと（仕組みの解説・実例分析で分かったこと）
- 実践内容（何を作った/直したか、動作確認結果）
- 気づき・発見（あれば）
- **成果物** — 生成・変更したファイルへのGitHubリンクを列挙する（下記参照）
- 次回予告

会話の中でその日実際に扱った内容を反映すること——テンプレートを機械的に埋めるのではなく、その日固有の学びを書く。

**成果物リンクの書き方** — リポジトリは `https://github.com/kiyo015/vibe-coding-study`。各ファイルは `https://github.com/kiyo015/vibe-coding-study/blob/day{N}/<リポジトリルートからの相対パス>` の形で、**その日のDay番号のタグ**でリンクする（例: Day11なら `.../blob/day11/study_plan_2weeks.md`）。タグはStep3でコミット後に打つ。

タグにする理由: 以前は`master`参照にしていたが、Day10で2つの問題が判明した。(1) リンク先のファイルが後日更新されると、過去の記録から新しい版が見えてしまう（その日時点の内容を指せていなかった）。(2) リンク先のファイルを移動・削除すると過去の記録のリンクが切れる。コミットハッシュ固定なら両方防げるが、commit前にはハッシュが確定しない。**タグ名はcommit前から決まっているので事前に書け、打った時点に永続的に固定される。**

### 1-2. 同じ内容のHTML版を作る

`summary.md`を書き終えたら、同じフォルダに`{YYYY-MM-DD}/summary.html`を作る。mdが記録の正本、HTMLは人に読ませる配布用という位置づけ。学習記録はメールに添付して送るので、GitHub上でソース表示になるmdだけでは読みにくい。

- **作る前に`html-report-design`スキルを読み込み、そのデザイン規則（CSSをそのまま使う・枠線カードや絵文字なし・各セクションにメッセージ行）に従う**
- 内容はmdと同じ。ただし文章を写すのでなく、比較は表、手順や流れは矢羽根、数値の差はSVGの横棒グラフなど、**図表中心に組み直す**。お手本は`2026-09-11/summary.html`（Day10）
- **1ファイル完結にする。** CSSはインラインで書き、外部のフォントやスクリプト、画像は読み込まない。メール添付で開いてもそのまま見られるようにするため。目安は数十KB以内
- 成果物リンクはmdと同じく`blob/day{N}/...`のタグ固定にする
- 書いたら、レイアウトが崩れていないか実際に描画して確認する。プレビューペインが非表示だと描画されないので、ヘッドレスChromeで画像化して見る（`chrome.exe --headless=new --screenshot=<出力先> --window-size=860,9000 file:///<パス>`）。スクリーンショットはスクラッチパッドに置き、リポジトリに入れない

mdとHTMLをこのStep1で両方作ってからStep3でコミットすることで、`day{N}`タグに2つとも含まれる（Day10ではHTMLをタグの後から追加したため、`day10`にHTMLが入っていない）。

### 2. 学習計画シートを更新

プロジェクトルート直下の`study_plan_2weeks.md` を開き、該当Dayの「学習履歴記入欄」のうち以下を埋める:

- 学んだこと（箇条書き、今日のsummary.mdの要点を凝縮したもの）
- 次アクション（次回Dayで何をするか）
- 完了チェック（`- [x] 完了`）

「実施時間」「つまずき」「気づき」は本人の内省が要るので、明示的に依頼されない限り空欄のまま残す。

### 3. Study全体をコミット・push

プロジェクトルート直下で:

```
git add -A
git commit -m "<その日の内容が分かる日本語メッセージ>

<その時点でシステムから指示されているCo-Authored-By行>"
git tag day{N}
git push
git push origin day{N}
```

- `Co-Authored-By`の行は、その時点でシステムから指示されている文言をそのまま使う。モデル名をこのスキルに固定で書かないこと（以前`Claude Sonnet 5`と固定で書いていたが、使用モデルが変わって古くなった）
- タグはStep1で書いたリンクの`day{N}`と一致させる。これを打たないとsummary.mdのリンクが全部404になる
- push先は既存のリモート（`origin`）にそのまま行う。新しいリポジトリを作ったりリモートを変更したりはしない

## 完了後の報告

何をコミットしたか（コミットハッシュとタグ）、summary.mdとsummary.htmlのパス（HTMLはファイルサイズも）、次回Dayの予定を簡潔に報告する。
