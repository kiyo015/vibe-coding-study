# ゲームバランスの調整

`mini-game`の難易度に関わる定数（`MIN_NUMBER`・`MAX_NUMBER`・`MAX_TRIES`）を変更する時の手順。

## なぜ手順が必要か

これらの定数は3箇所と連動している。片方だけ直すと、テストが落ちるか、ドキュメントが実態と食い違ったまま残る（Day1で学んだ「実態と乖離した記述」がまさにこれ）。しかも「範囲を広げる」と「試行回数」は数学的に連動しており、感覚で決めると理不尽なゲームになりやすい。

## 手順

### 1. 変更が妥当か確認する

範囲を変える場合、試行回数が足りているか必ず検算する。二分探索での最悪手数は `ceil(log2(範囲の広さ))`。

判断に迷う場合、あるいはユーザーが「難しくしたい」のような曖昧な要望を出した場合は、`references/difficulty-math.md` を読むこと。範囲ごとの推奨値の表と、手数を削った時に何が起きるか（どこから運ゲーになるか）、手数以外で難易度を上げる方法が書いてある。

### 2. 定数を変更する

`src/game.js` 冒頭のexport定数を書き換える。値を直接コードに埋め込まないこと（規約違反になる）。

### 3. テストを追従させる

`test/game.test.js` は固定乱数で答えを決め打ちしている。`MAX_NUMBER`を変えると期待値がずれるので、テスト内のコメント（`0.49 → 1 + floor(0.49*100) = 50`）ごと計算し直す。`MAX_TRIES`を変えた場合は上限到達のテストも確認する。

### 4. ゲーム仕様ドキュメントを更新する

`docs/game-rules.md` に定数の値と、その値にした理由が書いてある。値だけ直して理由を放置すると、次に触る人が判断できなくなる。

### 5. 動作確認

`npm test` で全件パスを確認する。UIの表示（残り回数）はロジックの定数を参照しているので、コード変更は不要なはず——もし`web/`側を直す必要が出たら、それは定数がUI層にハードコードされている設計上の問題なので、そちらを直す。
