02画面の流れ

締めの欄は経理と管理者だけ。参照は全員で、月から請求先へ、請求先から推移へとたどれる。

次に締める月経理・管理者だけ
締める終わった月だけ押せる
月の残高請求先ごと＋合計
請求先の推移古い順
  • 次に締める月: 最後に締めた月の翌月。まだ締めていなければ取引の一番古い月。取引が無ければ API は 204、画面は「締める取引（売上・入金）がありません。」。
  • 終わったか: その月の末日が日本時間の今日より前か。終わっていなければボタンを押せず「月末を過ぎてから締められます。」。
  • 締められない時: 締め忘れの請求先などの理由を画面に出し、移らない。
  • 404: 締めていない月・範囲外の年月、支店のコード・無い請求先の推移。
  • 営業の画面: 締めの欄を出さず、次に締める月も問い合わせない（締めと同じ権限の行）。

05V31 — 「テストで作れない」を作った

前の問い合わせを DB に送る直前で止めると、「後の問い合わせが先に返る」場面を決まった順で作れる。

請求先 A を選ぶ問い合わせを止める
請求先 B に選び直すB の結果が先に出る
A の問い合わせを流す古い結果が返る
B の請求書のままA の請求書は出さない

止める仕掛けは DbCommandInterceptor（HoldQuery）。画面は「結果が返った時の請求先が、今選んでいる請求先と同じ時だけ入れる」ので、古い結果を捨てる。この条件を外す誤り（S7）が落ちた。Day57 では未検出だった。

08フックの修正（Study の dev-guard）

会話を要約する前のフックは、既にある記録が書き出す内容の先頭と一致しなければ書き直さない。

10今日学んだこと

「作れない」「決まっていない」は、作り方と応答を決めればテストになる。

  • 非同期の順序は、DB に送る直前で止めれば作れる。Day57 で「作れない」と書いたのは、作り方を探していなかっただけだった。
  • 作る前に書き出した境目は、そのままテストになる。末日の当日 23:59 が無ければ X9 は落ちなかった。
  • 「無い」場合の応答は、決めないと決まらない。実装は null の 200 を返していた。API は 204、画面は文言と決めて固定した。
  • 参照と操作で権限の行を分ける。同じ画面でも、一覧は全員、次に締める月は締めと同じ行。営業の画面で問い合わせないことまで確かめた。

つまずき

  • ?? と is のパターンを混ぜて型が合わなかった → 補助関数 FirstDayOfMonth に分けた。
  • テストの準備を経理で行い受注を登録できなかった → 準備は管理者、月次締めだけ経理に切り替えた。
  • 営業の参照のテストで 409 → テストのデータで請求を締め忘れていた（実装は正しく止めていた）。
  • 締めの途中に次の画面を開いた → 移った URL を待ってから開いた。
  • C# ファイル2つに BOM が入った（Python の utf-8-sig）→ 差分で気付いて外し、以後は ed.py。
