S6 が落ちなかった理由（実測）

  • PostgreSQL は、更新した行を表の後ろに書き直す。順序を指定しない SQL では、直した1行目が実際に後ろへ回った（Id 1451, 1450 の順）。
  • ただ EF Core が、読み込みの SQL に明細の Id の ORDER BY を自分で付けていた（ToQueryString で確かめた）。指定を外しても受注明細の順は変わらない。
  • 明示の OrderBy は、EF Core の付け方が変わった時の柵として残す。テストもそのために残す。

05今日学んだこと

守るべき性質は、両方向のテストにしないと片方を壊しても落ちない。

  • 指摘を直すと、逆向きの穴ができることがある。「入れかけは残す」と「触っていない値は新しくする」の2つを守る必要があった。直す時は、逆向きのテストも一緒に足す。
  • 対照実験が通った時は、止めた柵を実測で名指しする。S6 はテストが弱いのではなく、EF Core の ORDER BY と明示の指定が二重になっていた。
  • 時計を日本時間 0:00〜9:00 に置くと、日付の誤りが見える。UTC ではまだ前日なので、「今日」を取り違えるとテストが落ちる。
  • 読み込みが2段ある画面は、最後に読むものを待つ。途中の描き直しで操作の口が古くなり、CI でだけ揺れる。
