### 指摘

#### Critical(必須修正)

**C1. `appsettings.Development.json:8-9` — 接続文字列とパスワードがリポジトリに入っている**
- 問題:`Password=<仕込みの架空の値>` がそのまま書かれています。
- なぜ問題か:秘密情報をファイルに書くことは禁止されています。user-secrets を使う決まりです(CLAUDE.md「DBの準備」)。
- 直し方:
  - この追加を消し、`dotnet user-secrets set ConnectionStrings:SalesCore ... --project src/SalesCore.Api` で設定してください。
  - コミットやpushが済んでいれば履歴に残るので、本人が `\password salescore_dev` でパスワードを変える必要があります。

**C2. `Invoice.cs:21-25` — 明細ごとに丸めた税額を足して請求額を出している**
- 問題:`LineTaxes` は明細ごとに `TaxOn` で税額を出し、`TotalAmount` はそれを合計しています。
- なぜ問題か:
  - 「消費税は税率ごとに1回だけ丸める」(business-rules.md §2)に、正面から反しています。105円×3行なら、正しい税額32円に対して33円になり、請求額が1円ずれます。
  - 1万件で約53%の請求書がずれることを測定済みのパターンです。
  - `Tax.TotalWithTax` とも食い違います。
  - `TaxCalculatorTests` は `TaxCalculator` だけを見ているので、このプロパティは強制の外です。
- 直し方:
  - `LineTaxes` を削除し、請求額は `Tax.TotalWithTax` を使ってください。
  - 明細欄に税額を出す要件があるなら、それ自体が業務ルールの変更です。先に決めて、文書に書く必要があります。

**C3. `SalesOrderLine.cs:56-57` — double と、キャストによる切り捨て**
- 問題:
  - `percent / 100.0` で `factor` が double になっています。型名を書かない double なので、SALES001 では止まりません。
  - `(long)(... * 100) / 100m` は切り捨てで、`Money.Round` を通っていません。
- なぜ問題か:
  - 例:33.33円を10%引きすると29.997になります。四捨五入なら30.00ですが、この実装では29.99です。
  - 丸めは `Money` の中だけで行うのが決まりです(business-rules.md §1)。
- 直し方:
  - 計算は decimal だけで行ってください(`1m - percent / 100m`)。
  - 単価を小数2桁に丸める処理は `Money` 側に用意し(例:単価用の丸め)、それを使ってください。
  - ただし C4 のとおり、この機能自体を入れてよいかを先に決める必要があります。

**C4. `SalesOrder.cs:80-87` — 伝票全体への値引きは「扱わない」と決まっている**
- 問題:`ApplyDiscount` は受注全体に値引きをかけます。
- なぜ問題か:business-rules.md §8 に「伝票全体への値引きは扱わない(2026-09-30 決定)。値引きは明細単位」とあります。要件そのものが業務ルールと矛盾しており、文書も直っていません。
- 加えて、実装にも次の問題があります。
  - 状態の検査が「取消でない」だけです。一部出荷・出荷済の受注でも単価が書き換えられます。
    - 計上済みの売上と `SalesAmount`(手元の数量 × 単価)が合わなくなり、累計差分の前提が壊れます。
    - その後の出荷・返品の金額もずれます。
  - `percent` の範囲を検査していません。負の値なら値上げになり、100を超えると単価が負になります。単価は0以上という決まりに反します。
- 直し方:業務ルールの変更として先に決めてください(`domain-rule-change`)。決まるまではこのメソッドを入れないでください。

**C5. `SalesOrder.cs:74-78` — 明細を物理削除している**
- 問題:`_lines.Remove(line)` で明細をリストから消しています。
- なぜ問題か:
  - 受注データを物理削除しないことは決まりです(business-rules.md §3・§7)。取消は状態で表します。
  - 状態の検査が「取消でない」だけなので、出荷済みの明細も消せます。売上のもとになった明細が消え、受注の状態判定(全明細の残りが0か)も変わります。
  - 自分の受注の明細かも検査していません。他の受注の明細を渡しても、`Remove` が false を返すだけで黙って何も起きません。
  - 最後の1行を消すと、明細が0件の受注が残ります。
- 直し方:
  - 削除ではなく、明細に取消の状態を持たせてください。
  - 許す状態は受付・承認済だけにし、他の受注の明細なら `ArgumentException` を投げてください。
  - 「明細の取消」を状態ごとの操作表(business-rules.md §3)に足し、文書を直してください。

**C6. `SalesOrder.cs:63-71` / `SalesOrderLine.cs:52` — 数量変更に検査がない**
- 問題:`line.ChangeQuantity` は値を代入するだけで、既存の `EnsureQuantity` も呼んでいません。
- なぜ問題か:
  - 0や負の数量を設定できます。
  - 出荷済み数量より小さくできます(観点として明記されている禁止事項です)。
  - 一部出荷・出荷済の受注でも変えられます。
    - 出荷済の受注で数量を増やすと、「出荷済」なのに残りがある状態になります。
    - 計上済みの売上に関わる値も変わります。
  - 承認済の受注で数量を増やすと、承認の基準額(100万円)を後から超えられます。段階2で問題になります。
- 直し方:
  - `EnsureQuantity` を呼び、`quantity >= ShippedQuantity` を検査してください。
  - 許す状態を決めて、状態ごとの操作表に足してください(少なくとも出荷済・取消では禁止)。
