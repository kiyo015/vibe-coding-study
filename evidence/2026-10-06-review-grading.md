## 方法

- レビュー役: `sales-core/.claude/agents/team-reviewer.md`（Day24 に業務ルールの観点を足した版）。`--agents` で定義をそのまま渡し、`--model` だけを haiku／sonnet／opus に変えた

## 判断

**レビュー役の model は opus にする**（`team-reviewer.md` の frontmatter に `model: opus`）。

- 検出が最も多く（10.8/11、ファイルを読める条件では3回とも11/11）、誤った記述が無い
- 3つのうちで最も速い（60秒。sonnet の約3分の1）
- 費用は sonnet の1.1倍、haiku の2.3倍（1回 $0.29）。レビューはマージ前に1回なので、見逃し1件の手戻りより安い
- haiku は11項目中平均4項目を見逃し、存在しない API を使った修正案が多い。誤りを「良い点」として褒めた回もあった。費用が安くても、レビュー役には使わない

## 注意（Day29 の CI に向けて）

- 条件A（差分だけ）でも opus は 10.7/11。CI で差分だけを渡す形でも使える
- **レビュー結果にパスワードの値を書き写す回が、どの model にもあった。** PR のコメントは公開されるので、CI では「秘密情報の値を出力に書き写さない」を指示に入れ、出力側でも検査する必要がある
- 採点は1人（Claude）が行った。基準は上の表のとおりで、「物理削除」の P6 は、規則に触れずに「出荷済みなら消せない」とだけ書いた回を不可にしている
